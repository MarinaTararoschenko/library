AIR DesignSystem

Button

v1.0

Elemento de acción principal del AIR Design System. Permite a los usuarios ejecutar acciones dentro de una interfaz — confirmar, cancelar, navegar o ejecutar operaciones. Disponible en 6 tipos visuales, 2 temas (primary/neutral), 2 modos (light/dark) y 6 tamaños.

01 Overview

Cuándo usarlo
  • Usar primary para la acción principal de una vista — máximo uno por sección visual.
  • Usar secondary o tertiary para acciones complementarias o de navegación.
  • Elegir el tamaño según el contexto: XS/S para espacios densos, L/XL/2XL para call-to-action prominentes.
  • Usar type="danger" o type="danger-text" únicamente para acciones destructivas.
  • Usar mode="dark" cuando el botón aparece sobre fondos oscuros o con imagen de fondo.
Cuándo no usarlo
  • No colocar más de un botón primary en la misma sección visual.
  • No usar danger para acciones neutras o de navegación — genera alarma innecesaria.
  • No combinar 3 o más botones del mismo tipo visual en una misma línea.
  • No usar el estado loading sin manejar el retorno al estado anterior cuando termina la operación.

04 Behavior

Interacciones y transiciones

El botón responde a hover, active/pressed y focus con transiciones de 150ms. En estado loading muestra un spinner y bloquea la interacción. En disabled reduce opacidad al 40%.

05 Accessibility

Criterios base

El componente Button renderiza un elemento <button> nativo, garantizando foco por teclado, activación con Enter/Space y soporte nativo de lectores de pantalla. El estado disabled deshabilita completamente la interacción.

Especificación técnica
  • Teclado: Tab para enfocar, Enter o Space para activar.
  • Foco visible: anillo de 3px con color del tema (--air-color-theme-background-a50).
  • disabled: usa atributo nativo disabled — no recibe foco ni puede ser activado.
  • loading: bloquea interacción con pointer-events:none — considerar aria-busy="true" en el contenedor.
  • iconLeft / iconRight: son decorativos (aria-hidden="true") — el label del botón es suficiente.
  • Contraste: todos los tipos cumplen WCAG AA (4.5:1) en ambos modos.

06 User Guidelines

Do

Usar un solo botón primary como CTA principal, acompañado de acciones secundarias.

Usar danger únicamente para acciones destructivas, con confirmación previa.

En mobile, adaptar el tamaño del botón al contenedor para mejorar el área táctil.

Don't

No usar múltiples botones primary en la misma sección — compiten por la atención del usuario.

No usar danger para acciones neutras — reservar el color rojo para acciones realmente destructivas.
